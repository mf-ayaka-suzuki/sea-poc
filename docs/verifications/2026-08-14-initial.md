# 検証 2026-08-14 — 初回（最小構成の立ち上げ）

## 目的

npmパッケージ（`lodash` / `dayjs`）を封入した最小構成のSEAバイナリを、macOS/arm64でビルドして動かす。
アプリロジックは持たず「封入パッケージが動く」ことの確認が主眼。

## 環境

- 既定 `node`: v18.20.8（Homebrew node@18）／バージョンマネージャ無し
- ビルド用に導入: `node@22`(keg-only, v22.23.2) → 最終的に土台は vendor同梱の公式 `v22.23.2`

## やったこと（時系列）

1. 環境確認。既定nodeが v18 で、`--experimental-sea-config` が `bad option`（→P1）。SEAは20+必須と判明。
2. `brew install node@22`(keg-only) を導入。既定 `node`(18) は変えない方針（→[D1](../decisions.md)）。
3. プロジェクト作成。`lodash`/`dayjs` を選定し、esbuildで単一JSにバンドルする構成に（→[D3](../decisions.md)/[D4](../decisions.md)）。
4. `build.sh`（bundle→blob→複製→注入→署名）を実装しビルド実行。
5. 3つの壁に当たり対処（下記）。
6. 成功・動作確認。

## ぶつかった壁

- **P2**: postject `Can't read and write...` → 複製したnodeが `0555`。`chmod u+w` を追加して解決。
- **P3**: postject `Could not find the sentinel NODE_SEA_FUSE...` → Homebrew版nodeはstripでfuse無し
  （`strings|grep -c` = 0）。**公式バイナリ**を `vendor/` に同梱（SHA-256照合、fuse=1）して解決（→[D2](../decisions.md)）。
